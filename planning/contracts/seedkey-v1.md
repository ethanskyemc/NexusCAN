# Contract: UDS SecurityAccess Seed/Key Providers — v1

Owner: team-lead. Code contracts (frozen signatures):
- Rust: `crates/nexus-protocols/src/uds/security/mod.rs` (DTOs, `KeyProvider`, `SeedKeyError`, hex helpers)
- TS: `src/types/seedkey.ts` (mirror + IPC command map + error parser)

Changing a DTO field requires updating BOTH files and notifying team-lead.

## 1. Concept
The ECU seed→key algorithm is unknown. Every key computation goes through a `KeyProvider`
built from a serializable `KeyProviderSpecDto` (`kind` tag). Providers are grouped in
per-ECU `SeedKeyProfileDto`s that bind requestSeed levels (odd, 0x01..=0x7D; sendKey = level+1)
to providers and carry known test vectors. Flow files reference `profileId` only.

| kind | crate | notes |
|---|---|---|
| builtin | nexus-protocols | demo algorithms, bit-exact with legacy TS `calculateKey` |
| table | nexus-protocols | exact seed lookup |
| script | nexus-protocols (feature `script`) | Rhai sandbox, `fn calculate_key(seed, level)` |
| library | nexus-seedkey-native | `GenerateKeyEx` / `GenerateKeyExOpt` via libloading |
| external_process | nexus-seedkey-native | no shell, placeholders, stdin, timeout+kill |
| http | nexus-seedkey-native | POST JSON, timeout |
| manual | HMI | backend returns `manual_required` |

## 2. IPC commands (Tauri + bridge, same names/args, camelCase)
| command | args | result |
|---|---|---|
| `cmd_seedkey_capabilities` | `{}` | `SeedKeyCapabilitiesDto` |
| `cmd_seedkey_list_profiles` | `{}` | `SeedKeyProfileDto[]` |
| `cmd_seedkey_save_profile` | `{ profile }` | `SeedKeyProfileDto` (id assigned if empty, timestamps set, validated) |
| `cmd_seedkey_delete_profile` | `{ profileId }` | `null` |
| `cmd_seedkey_compute` | `{ request: ComputeKeyRequestDto }` | `ComputeKeyResultDto` |
| `cmd_seedkey_compute_adhoc` | `{ provider, level, seedHex }` | `ComputeKeyResultDto` (test unsaved form) |

| `cmd_seedkey_probe_library` | `{ path }` | `SeedKeyLibraryInfoDto` (app never loads the file; header read in-app, export probe in the helper process) |

Errors: string `"[seedkey:<code>] <message>"` (`SeedKeyError::to_ipc_string`). Bridge: HTTP 400 with that string
through the existing `bad_request` path. HMI: `parseSeedKeyError()`.

## 3. Portable providers (protocol-specialist)
- builtin: `xor_ff, xor_const, sum_negate, add_const, right_rotate, crc16_kermit, crc32`; constant default `5A3C1E8F`.
  Must match legacy TS (`FlowEngine.ts` `calculateKey`, `crc16ibm`, `crc32`, `ror32`) byte-for-byte, incl. short-seed quirks.
  Parity vectors generated by running the TS functions with node and hard-coded into Rust tests.
- table: normalized hex compare; miss → `NotFound`.
- script (Rhai): `Engine::new_raw()`-style minimal engine + needed packages; no modules/import, `eval` disabled,
  max operations, call depth, string/array/blob sizes bounded; wall-clock timeout via `on_progress`.
  `seed` passed as Blob, `level` INT; return Blob or Array of INT 0..=255; otherwise `Script` error.
  AST compiled once per provider.
- `validate_profile`: schema version, name non-empty, ≥1 level, levels odd & unique, test vector levels exist,
  hex fields parse, seed/key ≤ 256 B, native fields non-empty, script ≤ 64 KiB, timeouts 1..=60000 ms.
- `run_test_vectors`: evaluates all vectors, never short-circuits; `manual` vectors → outcome with `manual_required` error.

## 4. Native providers + policy (backend-dev)
- library (**v1.1 — out-of-process, team-lead decision**): vendor libraries are NEVER loaded in-process.
  `nexus-seedkey-native` validates the path (absolute, regular file, `.dll`/`.so[.N]`/`.dylib`), reads the
  PE/ELF/Mach-O header WITHOUT loading it, and spawns the matching helper `nexus-seedkey-host32` / `nexus-seedkey-host64`
  (lookup: next to `current_exe`, then `NEXUS_SEEDKEY_HOST_DIR`; dev build name `nexus-seedkey-host` accepted for the
  native flavour). Helper missing → `BitnessMismatch` with an actionable message.
  Helper protocol: one JSON line on stdin (`{"op":"compute"|"probe",...}`), one JSON line on stdout, exit
  (0 ok, 2 handled error, other = library crashed). Cleared env, cwd = library dir, timeout 5 s (child killed),
  stdout ≤ 64 KiB. A crashing vendor DLL only kills the helper.
  Prefer `GenerateKeyExOpt` when `options` set, else `GenerateKeyEx`. ABI (Vector AN-IDG-1-017):
  `int GenerateKeyEx(const u8* seed, u32 seedLen, u32 level, const char* variant, u8* key, u32 maxKeyLen, u32* actualKeyLen)`
  `int GenerateKeyExOpt(const u8* seed, u32 seedLen, u32 level, const char* variant, const char* options, u8* key, u32 maxKeyLen, u32* actualKeyLen)`
  return 0 = OK; non-zero → `LibraryCall{code}`; `actualKeyLen > maxKeyLen`, crash or malformed helper reply →
  `LibraryFault` (wire code `library_call`). On 32-bit x86 the helper calls through an SP-restoring trampoline so both
  cdecl and stdcall exports work; decorated names `_GenerateKeyEx@28` / `_GenerateKeyExOpt@32` are also tried.
  Packaging: one cargo bin renamed to `…host64` (native) and `…host32` (i686 build) via Tauri `bundle.externalBin`.
  `cmd_seedkey_probe_library` reads the header in-app; export detection runs inside the helper.
  Capabilities add `nativeKindsAvailable`, `libraryHost32Found`, `libraryHost64Found`.
  Library paths are local-only data: never part of cloud sync payloads.
- external_process: `std::process::Command` (no shell), cleared env except PATH/SystemRoot, timeout + kill, stdout ≤ 64 KiB.
- http: POST JSON, rustls, timeout, response ≤ 64 KiB.
- **Policy:** Tauri desktop → native allowed. Bridge → native kinds (compute, adhoc, save, probe) allowed ONLY when
  peer IP is loopback AND env `NEXUS_BRIDGE_ALLOW_NATIVE_SEEDKEY=1`; otherwise `NativeNotAllowed`.
  `cmd_seedkey_capabilities.nativeProvidersAllowed` reflects this per caller.
- Profile store: one JSON file `seedkey_profiles.json` next to the existing projects dir convention
  (`locate_projects_dir()` parent / Tauri app data dir), atomic write (tmp + rename), schema version checked.

## 5. HMI (frontend-dev)
- UDS Flow blocks: `uds_security_request_seed` (27 odd), `uds_security_compute_key`, `uds_security_send_key` (27 even),
  composite `uds_security_access` kept ("Security Unlock") + "Expand" action producing the three blocks.
- Compute Key sources: `profile` (backend), `manual` (operator modal), `key_in` passthrough, `legacy_js` (sandboxed Worker).
- Seed/Key profile manager with per-kind forms, test vectors, library probe, capabilities-aware native kinds.
